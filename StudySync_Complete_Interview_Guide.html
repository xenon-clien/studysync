3. Top 15 Viva & Technical Interview Questions & Answers

Q1: Why did you choose React 19 and Vite over Next.js or Create-React-App?
"Create-React-App is deprecated and uses sluggish Webpack builds. Vite uses native browser ES modules during development and Rollup for production, reducing build times from minutes to milliseconds. We chose pure React SPA over Next.js because StudySync is an interactive dashboard application where state lives on the client (real-time Pomodoro timers, local storage fallback, dynamic SVG diagrams); full server-side rendering (SSR) would add unnecessary cloud server cost and hydration overhead without adding value to an authenticated student portal."
Easy way: Vite Webpack se 100x fast hai. Aur Next.js SSR ki zaroorat nahi thi kyunki yeh ek internal dashboard app hai jisme dynamic client timers aur charts hain.
Q2: How is state managed across StudySync? Why not Redux?
"We built a centralized state engine using React's Context API (StudyContext.jsx). Redux requires heavy boilerplate (actions, reducers, dispatchers, store configuration). For StudySync, Context API combined with custom hooks (useStudy()) provides a clean, predictable single source of truth for user auth, themes, study schedules, and entity CRUD operations. It also incorporates optimistic UI updates and local storage persistence with zero external bundle weight."
Easy way: Redux bohot heavy aur complex ho jata. Context API se saara data (auth, tasks, schedule) ek jagah rehta hai aur bina kisi extra library ke clean rehta hai.
Q3: How does the custom SVG Vector Diagram Engine work?
"In VisualDiagram.jsx, we avoided heavy 3D or canvas libraries like Three.js. Instead, we developed a pure Scalable Vector Graphics (SVG) engine using geometric SVG elements (<path>, <circle>, <rect>, <text>). It dynamically renders responsive architectural diagrams for complex CS concepts: AVL Tree balance rotations (LL, RR, LR, RL), B+ Tree multi-way splits, Hasse Diagrams for POSETs, OSI 7-Layer stacks, and Gradient Descent curves. Because they are pure SVGs, they look razor-sharp on Retina screens and load instantly."
Easy way: Humne bina kisi third-party library ke pure SVG vectors use karke AVL tree rotations aur B+ tree ke crisp diagrams banaye hain jo instant load hote hain.
Q4: What is Optimistic UI Updating and where is it used?
"Optimistic UI updating is a pattern where the client updates its interface immediately under the assumption that the backend request will succeed. In StudySync (optimisticAdd, optimisticUpdate, optimisticDelete), when a student adds a task, ticks a checkbox, or logs a Pomodoro session, the UI updates instantly with a temporary ID (uid('item')). The API call executes asynchronously in the background. If the server responds with the saved MongoDB document, the temp ID is replaced. If it fails, the change is reverted."
Easy way: Jab user checkbox click karta hai, screen turant update ho jati hai bina server response ka wait kiye. Server par request peeche se jati hai, jisse app super-fast lagti hai.
Q5: How does Authentication & Authorization work?
"We use stateless JSON Web Tokens (JWT). Upon login, the backend verifies the user's password using bcrypt.compare() against the 10-round salted hash. If valid, it signs two tokens: an Access Token (30-day lifetime) and a Refresh Token (7-day lifetime). Tokens are transferred via secure HTTP-only cookies as well as Bearer tokens in headers. Protected routes verify the token using authMiddleware.js, decoding the user ID and role before granting access."
Easy way: Passwords bcrypt se encrypted rehte hain. Login ke baad JWT token milta hai jo HTTP-only cookie aur authorization header ke zariye secure rehta hai.
Q6: Why MongoDB instead of PostgreSQL or MySQL?
"StudySync deals with semi-structured and hierarchical academic data. An Exam Prep Pack contains syllabus units, crash analogies, and past questions with varying mark structures (1M, 2M, 5M, 10M). In a relational SQL database, this would require 5-6 tables with extensive JOIN operations. In MongoDB, a syllabus pack and its PYQs are stored as a single, expressive, schema-flexible BSON document, allowing ultra-fast read queries."
Easy way: Exam syllabus aur questions nested hote hain. SQL me 5 alag tables jodna padta; MongoDB me poora unit aur questions ek hi document me fast store ho jate hain.
Q7: How did you fix the HTTP 405 (Method Not Allowed) error on Vercel?
"When deploying the frontend to Vercel, submitting the login form returned an HTTP 405 error. The root cause was that Vercel was only hosting the static React build. Without a separate backend URL configured, the frontend sent a POST request to /api/auth/login on the same domain. Vercel's SPA routing rewrote that to index.html, which cannot accept POST requests. We fixed this by implementing Dual-Mode Resilience in StudyContext.jsx: the client attempts the backend API, but if an HTTP 405 or network disconnect occurs, it gracefully activates an offline Demo Mode with local seed data, ensuring the app never breaks for evaluators or recruiters."
Easy way: Vercel par backend na hone ki wajah se request index.html par chali gayi jo POST accept nahi karta. Humne smart fallback add kiya: agar backend offline ho ya 405 de, toh app bina crash huye Demo Mode me chalne lagti hai.
Q8: How does the Pomodoro Timer integrate with user analytics?
"The Pomodoro timer (TimerPage.jsx) runs a 25-minute focus countdown. When a session completes, it calls logPomodoroSession(minutes, subjectId). This function updates total focus minutes, logs the session timestamp, attributes the hours to the selected subject, updates the daily habit streak, and sends the payload to /api/pomodorostats. The user's Dashboard and Analytics pages immediately re-render with updated charts."
Q9: What security measures did you implement on the Express backend?
"We applied Defense-in-Depth security: 1) helmet() sets HTTP security headers. 2) express-mongo-sanitize prevents NoSQL injection by stripping '$' and '.' characters. 3) express-rate-limit blocks brute-force attacks (1000 requests per 15 minutes). 4) CORS origin whitelist ensures only authorized domains can access cookies and APIs. 5) Joi schemas validate all request bodies."
Q10: If you had to scale StudySync to 100,000 active students, what would you do?
"1) Database: Use MongoDB Atlas replica sets with read replicas and shard on university. 2) Caching: Place a Redis cache in front of syllabus and PYQ queries (which are 90% read-heavy). 3) CDN: Cache SVGs and static builds on Cloudflare Edge. 4) Microservices: Split the Exam Prep content API from the real-time user study tracker into containerized Docker services running on Kubernetes with auto-scaling."
